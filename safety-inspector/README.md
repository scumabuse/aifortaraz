# Цифровой инспектор ОТ

Локальное приложение для видеомониторинга охраны труда. Внешний модуль ИИ
передаёт детекции, события и статистику. Интерфейс показывает камеры и тревоги,
позволяет вести журнал инцидентов, строить аналитику и формировать документы.
В демо-режиме весь сценарий доступен с синтетическими данными.

## Быстрый запуск

Нужны Python 3.11+ и Node.js 22+. На Windows из корня проекта выполните:

```powershell
if (!(Test-Path .env)) { Copy-Item .env.example .env }
python -m venv .venv
.\.venv\Scripts\python -m pip install -r backend/requirements.txt
npm --prefix frontend ci
.\.venv\Scripts\python scripts/dev.py
```

Если зависимости уже установлены, достаточно последней команды. Если в venv
нет pip, используйте `python -m pip --python .venv install -r backend/requirements.txt`.
На Linux/macOS после установки зависимостей запустите `make dev` или
`.venv/bin/python scripts/dev.py`. Ctrl+C завершает локальные серверы.

Откройте [приложение](http://localhost:5173), вход **admin / admin**.
[Swagger](http://localhost:5173/api/docs) и [состояние API](http://localhost:5173/health)
доступны на том же адресе. Миграции применяются при старте. Демо-история за 30 дней
заполняется в фоне и сохраняет прогресс между запусками.

| Логин / пароль | Доступ |
|---|---|
| admin / admin | Все страницы, пользователи и API-ключи |
| engineer / engineer | Камеры, зоны, инциденты, отчёты и настройки |
| master / master | Просмотр и работа с инцидентами своего участка |
| viewer / viewer | Просмотр |

Для установки на чистую машину нужна сеть или заранее подготовленные зависимости.
Для первого контейнерного запуска создайте .env из примера и выполните
`docker compose -p inspector up --build`. Интерфейс откроется на
[порту 8080](http://localhost:8080). Для офлайн-переноса заранее выполните
`docker compose -p inspector build` и
`docker save -o inspector-images.tar inspector-backend inspector-frontend`.
На целевой машине загрузите архив через `docker load -i inspector-images.tar`
и запустите `docker compose -p inspector up --no-build --pull never`.
Во время работы интерфейс, звук, Swagger, шаблоны и графики используют локальные
ресурсы. Telegram и внешние видеопотоки требуют связи со своим источником.

SQLite и снимки хранятся в `./data`. Переменные окружения описаны в `.env.example`.
Для PostgreSQL укажите `postgresql+psycopg://user:password@host:5432/inspector`
в DATABASE_URL. Перед развёртыванием замените демонстрационные пароли и JWT_SECRET.

## Демонстрация за несколько минут

1. Откройте [Live](http://localhost:5173/live). Четыре камеры показывают поток
   или анимированную схему. Включите звук кликом по кнопке в шапке.
2. Во второй вкладке откройте дашборд или журнал. На Live нажмите
   «Симулировать инцидент» и выберите «Падение человека». Проверьте появление
   инцидента, уведомление и критический баннер. Нажмите «Принять» и откройте
   таймлайн. Среднее время реакции обновится на дашборде.
3. В аналитике смените период и участок. На плане нажмите маркер камеры,
   чтобы открыть её журнал. Данные экспортируются в CSV из журнала и аналитики.
4. В карточке инцидента нажмите «Составить акт», откройте предпросмотр,
   сохраните акт и выберите «Печать / PDF» → «Сохранить как PDF».
   Сводка и предписание доступны в разделе «Отчёты».
5. Откройте [страницу проекта](http://localhost:5173/about) и
   [видеостену](http://localhost:5173/wall). Метрики mAP, FPS и задержки
   заполняются в «Настройки → Метрики модели». На видеостене включите
   полноэкранный режим. При наличии более четырёх камер можно переключать
   группы автоматически или вручную.

Демо-режим можно выключить, изменить его интенсивность или пересоздать
историю в настройках. Реальные записи сохраняются при сбросе демо.

## Подключение внешнего ИИ

1. Войдите администратором. В «Настройки → API-ключи» создайте ключ и скопируйте
   его при создании. Скопируйте id камеры из раздела «Камеры» (демо-камеры: cam-1…cam-4).
   Ключ `ai-module` создаётся при старте: из SEED_AI_API_KEY либо случайный, который
   один раз печатается в консоль и сохраняется в `.secrets/ai_api_key`.
2. Сохраните полигон и правила в редакторе зон. Проверьте конфигурацию через
   GET /api/v1/ingest/config/{camera_id} с заголовком X-API-Key.
3. Запустите тестовый клиент из корня проекта:

```powershell
.\.venv\Scripts\python scripts/fake_ai_client.py --host http://localhost:5173 --camera UUID_КАМЕРЫ --duration 35
```

Ключ вводится скрыто. Для автоматизации есть `AI_API_KEY` и `--api-key`.
Клиент читает конфиг, отправляет heartbeat каждые 5 секунд, синтетические
детекции и событие сразу при старте, затем раз в 30 секунд. Используйте
`--no-events`, если нужны только детекции и heartbeat. При действующем кулдауне
следующее событие может получить HTTP 202. На этой камере моки приостанавливаются
и возобновляются после 60 секунд тишины.

Для проверки MJPEG добавьте `--push-frames`. В настройках камеры выберите
тип `mjpeg` и адрес `/api/v1/stream/UUID_КАМЕРЫ.mjpeg`. Для снимков из локального
файла добавьте `--video путь.mp4`, а для веб-камеры — `--webcam УСТРОЙСТВО`.
Эти два режима требуют FFmpeg в PATH. Укажите имя устройства DirectShow на
Windows, индекс AVFoundation на macOS или `/dev/video0` на Linux.
`detect(frame)` — точка подключения реального детектора в отдельном процессе.
См. [контракт API](docs/API.md).

Демо-видео можно положить в `frontend/public/demo/cam1.mp4` … `cam4.mp4`.
Обычный RTSP в браузере требует релея в MJPEG или HLS. Внешний HLS должен
разрешать CORS. Браузерная webcam требует разрешения пользователя и
localhost либо HTTPS.

## Running with the other half

This website is one half of the integration; the AI module is a separate repository
(`safety-ai`). How to run both together is described in the
[integration root README](../../README.md); the contract between them is
[docs/CONTRACT.md](docs/CONTRACT.md). Ports: 8000 backend API, 5173 Vite dev frontend,
8080 Docker (nginx) frontend, 8001 MJPEG streams of the AI module. The backend reads
`SEED_AI_API_KEY`, `AI_CAMERAS`, `AI_MJPEG_BASE_URL` and `DEMO_MODE` (see `.env.example`).

## Telegram и отчёты

В «Настройки → Уведомления» сохраните токен, Chat ID и подпись получателя.
Бот должен иметь доступ к чату. «Отправить тест» ставит сообщение в очередь.
Результат появится в журнале. Для автоматической отправки включите её,
укажите базовый URL сайта и задайте фильтры, тихие часы и кулдаун.
Снимок отправляется через sendPhoto, при отсутствии снимка отправляется текст.
Временная ошибка даёт до трёх повторов. Демо-события включаются отдельным флагом.

Отчёты используют серверные шаблоны. Скачанный HTML содержит стили и снимки.
Для PDF используйте печать браузера. Снимки в сохранённых документах остаются
доступны после очистки старых снимков из журнала.

## Проверки и структура

```powershell
Push-Location backend
..\.venv\Scripts\python -m pytest -q
Pop-Location
npm --prefix frontend test
npm --prefix frontend run lint
npm --prefix frontend run build
```

`make check` выполняет все эти проверки и ruff на Windows и Linux/macOS.

`backend` — FastAPI, SQLAlchemy, миграции и шаблоны.
`frontend` — React, Vite, Tailwind, Recharts и react-konva.
`scripts` — запуск, сид и тестовые клиенты.
`docs` — [контракт API](docs/API.md) и [отчёт по критериям готовности](docs/READINESS.md).
